# Proxy Checker v6.6.4 — 来源轮转、发现保底与累计统计

## 修复

- 修复持续维护的来源队列串行阻塞：每源独立保存剩余候选，一个小批次就轮转，第一源未排空也能检测第二源。
- 连续复测增加默认 120 秒耗时预算，批间检查；零散到期项不再连续占批。保留 `refresh_share` 上限、15 分钟复测目标、单批预算及检测门槛，不提高并发。
- 页面区分本批与升级后累计，新增来源覆盖、当前来源、最近成功抓取及累计拉取／检测／增改删。真实提交与计数原子落盘，重复提交不重复累计。
- 保留旧候选、在途恢复、独立重试、取消栅栏和人工修改保护。多来源候选合计限额 100000，独立重试限额 50000；容量不足显式让出，不截取来源头部。

## 验证

- [修复前失败回归](https://github.com/fujunchao/proxy-checker/actions/runs/38578198810)：大来源阻塞、零散复测连批、复测耗时无保底三项均在真实协调器上失败。
- 新增确定性回归覆盖来源整轮、旧队列迁移、重启恢复、慢项重试、容量背压、读源失败、抓取期间人工清空，以及累计提交的故障重试幂等。
- 本地隔离临时目录执行合成后端回归和前端真实 DOM 检查；完整 CI 继续覆盖既有后端／前端、仓库策略、Z.AI、分页性能、身份及 fixed/isolated Docker 冒烟。最终版本仅在对应 SHA 完整 CI 通过后发布。

## 升级说明

- 镜像：`ghcr.io/fujunchao/proxy-checker:v6.6.4`，发布工作流同时更新 `latest`，构建 linux/amd64 和 linux/arm64。
- 只发布，不自动部署、重启服务或修改用户配置。已启用持续模式的实例在升级后采用新调度，旧 `enabled`、skip/force、档位及入库策略不变。
- 持续模式仍支持 22/33 个纯文本来源，此补丁没有接入另外 11 个来源。
- 来源按批轮转不代表实时重新下载；已缓存的该源队列处理完后再抓取，成功抓取后至少冷却 300 秒。复测耗时预算在批次结束检查，不是硬性时延保证。
- 累计只统计新版本维护事件，跨档位保留，新增和移除为条次；不将旧文件或最近 20 批历史伪装为完整累计。
- 回退仍须先关闭维护、保留数据备份，并用 `tools/export_legacy_repo.py` 导出当前权威仓库。旧持续模式不认识多来源队列，不应直接回退并继续使用旧模式维护器消费新队列。

详情见 [实施方案](implementation-plan-v6.6.4.md) 和 [持续维护说明](continuous-maintenance.md)。
