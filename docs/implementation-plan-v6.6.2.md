# v6.6.2 大批量结果性能优化实施计划

日期：2026-10-14。范围：四项性能优化，包含此前已完成的线性批量合并、加载提示和断线重试。保持代理判定、仓库策略、固定身份及订阅链接不变；本次发布不等于自动更新用户的线上容器。

## 1. 任务摘要与结果分页

- 保留旧版状态接口契约；新前端请求不带结果的轻量摘要。
- 新增独立结果分页接口，每页最多 1000 条，通过任务 ID 和原始结果游标续传。
- 摘要与分页分别轮询，先显示后台进度；分页之间让出事件循环。
- 完成、停止、失败后的最后一轮结果短期保留 15 分钟，避免任务结束时漏掉尾页；新任务使旧分页失效，过期明确返回错误。
- 验收：摘要大小不随结果数量增长；50000 条结果能无遗漏分页恢复；覆盖任务切换、尾页、停止及过期。

## 2. 检测历史增量同步

- 新增幂等追加接口，服务器加锁合并、原子落盘；无新增时不重写文件。
- 前端只排队新增历史，按最多 1000 条一批合并上传，失败保留队列重试；已有服务器历史不反复上传。
- 清空仍是明确的替换操作，与进行中的追加串行执行，避免清空后被旧请求恢复。
- 旧服务端通过能力协商保留原同步方式。
- 验收：50000 条既有历史新增 1 条仅上传 1 条；覆盖失败重试、并发追加、清空及不重复写盘。

## 3. 异步本地缓存与写入合并

- 结果快照改用 IndexedDB 异步存储，写入按时间窗口合并，不再每次轮询同步序列化全部结果。
- 检测历史的本地写入同样合并；不可用环境采用有界本地缓存降级，不影响后台任务。
- 兼容旧 localStorage 缓存；迁移成功后移除旧结果快照；清空与异步恢复使用版本保护，迟到的读取不能覆盖新结果。
- 验收：多次快速更新只落盘一次；覆盖恢复、迁移、缓存禁用、写入失败、身份隔离及清空竞态。

## 4. 列表局部更新

- 有效、失效、仓库列表按代理键复用 DOM 节点，仅插入、替换、移动或删除变化行。
- 保留首屏数量限制、显示更多、筛选、分类迁移及已有操作按钮；尽量保留展开状态和滚动位置。
- 验收：重复渲染不重建未变化行，单条更新不替换整表；在真实 DOM 实现上验证筛选、空态、删除索引与展开状态。

## 执行与发布顺序

1. 各项先补能够失败的回归测试，再实现并验证；记录性能和响应大小。
2. 运行全部前端、身份、仓库策略、Z.AI、完整 HTTP 冒烟；将新增测试纳入 CI。
3. 更新页面、镜像示例、产品说明与发布说明为 v6.6.2。
4. 审查差异及敏感文件，提交并推送；等待分支 CI 成功，再打 v6.6.2 标签。
5. 等待标签的测试和多架构镜像发布成功，再发布 GitHub Release，报告提交、标签和镜像状态。
