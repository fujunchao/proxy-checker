# Proxy Checker v6.6.5 — 待检去重、缓存补量与复测选批

## 改进

- 持续维护在同一工作区的来源队列、在途输入和未完成重试之间合并相同端点，保留多个来源归属。协议和认证凭据仍参与身份判断；完成后重新抓取的候选仍按原有 `force/skip` 处理，不新增永久跳过或失败冷却。
- 发现按过滤后的有效输入计算批量，不足时从其他来源的已有缓存补量。主来源公平轮转不被补量游标跳过；每个来源优先批最多抓取一个来源，不为凑满连续等待多个网络来源。读源失败或容量不足时仍可处理已有缓存。
- 修复已完成节点再次到期后，被旧的“本轮已尝试”集合阻挡的问题。未完成项保留退避和轮转，已提交的完成时间能在重启后解除残留尝试标记。
- 页面和运行记录增加本批多来源、有效输入、过滤数、重复合并数及选批耗时；新抓取与缓存处理分开计数。增加脱敏选批日志，便于后续核对吞吐和库存新鲜度。

## 保持不变

- 不增加并发上限，不更改检测轮数和 Z.AI / ZCode 门槛，不修改公共订阅格式和入库策略。
- 批内继续并发检测，检测与增量发布并行；同一工作区仍只有一个维护批次，同一仓库提交仍串行。
- 默认 15 分钟复测目标、100 / 200 条批量上限、120 秒批次预算、连续复测预算及每 20 条 / 10 秒发布节拍不变。目标不是硬性时限保证。
- 保留现有库存、旧候选队列、已检测历史、取消和人工编辑栅栏；唯一候选不因容量限制被截断或清空。
- 仍支持 22/33 个纯文本来源。本补丁不包含来源定期增量刷新、失败冷却、快速淘汰或跨批次动态工作池。

## 验证

- 先复现“旧尝试标记阻止再到期”“失败候选跨源重复检测”“过滤后空批次不补量”和新状态字段缺失，再逐项实现。
- 真实协调器回归覆盖跨源与重试去重、协议及凭据身份、过滤后补量、来源公平轮转、网络抓取上限、容量原子接纳、旧状态迁移、混合来源部分提交后恢复以及 `force/skip` 兼容。
- 前端使用真实 DOM 验证多来源展示、统计口径、转义及旧状态兼容；原有仓库、Z.AI、身份、分页性能、完整冒烟及 Docker fixed/isolated 门禁继续执行。
- 发布仅在工作分支、main 和标签对应 SHA 的完整 GitHub Actions 验证通过后完成，并核验双架构镜像与 `latest`。

## 升级

- 版本镜像：`ghcr.io/fujunchao/proxy-checker:v6.6.5`，发布同时更新 `latest`，支持 linux/amd64 与 linux/arm64。
- 本次只发布，不自动部署、重启服务或修改用户配置。用户自行升级后，已启用持续维护的任务使用新选批策略。
- 来源队列仍保持每源列表结构，新增来源归属和尝试时间元信息；重启不重放内存成功观测，只恢复未处理输入。
- 首次加载旧队列会合并重复候选，因此待检数可能下降；这不代表丢失了唯一候选。新指标为本批统计，不回填旧批次累计。
- 回退前保留数据备份，并遵循 [持续维护说明](continuous-maintenance.md) 的仓库导出和版本兼容流程。

具体范围见 [实施方案](implementation-plan-v6.6.5.md)。真实吞吐提升与节点留存收益仍需升级后对照观测，不以合成测试冒充线上实测。
