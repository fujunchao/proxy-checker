# v6.6.5：提高现有检测并发的有效利用率

## 目标与证据

2026-10-16 用户提供的日志显示：最近六小时新增与复测分别占批次耗时的 48.5% 和 51.5%，不是固定 1:4。154 个复测批次中有 107 批不足 25 条，且出现到期 97 条却仅选中 24 条；来源队列的 11269 条候选中有 1396 条重复项。原始日志、节点地址和工作区身份不进入仓库。

本版本落实用户确认的第一阶段：跨来源待检去重、发现批次补量、复测按真实到期时间选批。目标是减少重复输入和零散批次占时，不以增加并发、放宽检测门槛或推迟复测来制造吞吐增长。

## 实施顺序

### 一、完成观测与未完成尝试分开排期

- 使用 `last_checked_at` 判断是否到期，并维持最老优先。
- 已完整检测的节点不再因旧的 `refresh_seen` 集合，在再次到期后被排除。
- 未完成项保留尝试集合和退避，防止少数慢节点反复抢占最老前缀；未知时间仍优先。
- 升级时迁移旧尝试集合，不能把旧成功标记当成永久排除项。重启后仍只信任已提交的完整检测时间。
- 保留 900 秒默认目标、100 条复测上限、连续批数和耗时预算、零散批次让出规则。此版本不承诺硬性复测时限。

### 二、待检输入统一去重并保留来源归属

- 在单工作区的来源队列、未完成重试和在途输入之间，以规范化端点建立有界索引；协议和凭据仍参与身份判断。
- 一个待检输入只检测一次，其多个来源归属合并保存。不同工作区或档位之间不共享检测结论。
- 仅合并仍待处理的重复项。完成后再次抓取的候选依旧遵循原有 `force/skip`，不增加失败冷却或永久黑名单。
- 旧单队列、每源队列、退役来源、在途恢复均兼容；仍保留每源 50000、来源队列合计 100000、重试 50000 的限额。超限不截断来源，不丢已接纳的唯一候选。

### 三、在有效输入不足时从已有缓存补量

- 主来源按现有游标公平轮转，先过滤已有库存和 `skip` 历史，再计算有效批量。
- 不足 `discover_batch` 时，按轮转顺序从其他来源缓存补量；重试优先批可在处理重试后用缓存补量。
- 每个来源在单次选批中最多扫描一遍，受已有队列容量约束；不为填满一批串行抓取多个网络来源。
- 每个来源优先批最多抓取一个源；缓存补量不跳过其他来源应有的主轮转机会。无足够候选时立即以小批次运行，不等待未来输入。
- 在任何检测开始前，完整批次及来源归属必须可恢复。取消、人工修改和配置变更仍使旧结果失效。
- 同一批内部继续并发检测，检测与发布继续并行，同一仓库提交仍串行；不引入多个互相竞争的维护批次。

### 四、补充可观测性

- 兼容原单来源字段，增加本批涉及的来源列表、有效输入、过滤数量、合并重复数量和选批耗时。
- `source_count` 继续只表示本批真实新抓取的候选，缓存补量不冒充新抓取；新增字段明确为本批指标，不伪造历史累计。
- 日志不打印节点、凭据、订阅链接；页面对来源名称进行转义，并兼容旧状态缺少新字段。

## 本次不做

- 不更改并发上限、两轮检测、Z.AI / ZCode 门槛、稳定性和公共订阅语义。
- 不新增“快筛失败即完整失败”，不跳过任务级未完成的真实性检查。
- 不做失败冷却、来源定期增量刷新、来源质量权重、跨批次动态工作池和数据库重构。
- 不自动部署、不重启现有服务、不接触用户导出的生产数据。

## 已确认的测试接缝与验收

用户已确认沿用三个现有接口：

1. 真实 `execute_maintenance_run` 协调器：注入合成来源、检测器和受控时钟；验证实际检测输入、顺序、过滤、补量与来源公平性。
2. `Repository` 发布和读取接口：验证原子累计、幂等、重启恢复、取消和人工编辑栅栏；不以另外一套调度模拟替代真实路径。
3. 前端状态展示：真实 DOM 验证多来源及本批指标、转义、旧字段兼容，不改变累计口径。

按纵向小步执行“失败用例 → 最小实现 → 回归”，不一次性编造全部测试。保留已有发现公平性、仓库策略、Z.AI、工作区、分页性能及 Docker fixed/isolated 门禁。

## 发布门禁

- 在 `codex/v6.6.5-pipeline` 工作分支实施；本地临时目录验证，不使用真实工作区数据。
- 工作分支完整 GitHub Actions 通过后，确认远程 main 未出现并行变更，再快进 main。
- main 同一 SHA 完整 CI 通过后创建并推送 `v6.6.5` 标签。
- 标签工作流再次完整测试并发布 linux/amd64、linux/arm64 镜像；核验标签、镜像 revision、`latest` 一致性后发布 GitHub Release。
- 最终报告区分“已发布”与“已部署”，并保留方案、回归和发布说明。
